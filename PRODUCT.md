# Product

## Register

product

## Users

The primary user for the first version is one company operator who runs the whole TikTok content loop end to end: importing viral videos, confirming video segments, preparing AI prompts, reviewing analysis results, managing reusable factors, selecting SKUs, producing scripts and prompts, recording published video performance, and feeding results back into the factor library.

The product is intended for company-internal use. It will be developed on macOS and later deployed on a Windows computer for access over the company LAN. The first version does not include login or role-based permissions.

## Product Purpose

DuoLe TikTok Growth Studio is a company-internal workbench for turning viral TikTok videos into reusable content-production assets. It supports a closed loop from viral video analysis, segment evidence extraction, nine-part structure judgement, execution factor capture, SKU-based content production, publishing-result recording, and factor effectiveness evolution.

The system is not a one-off video analysis tool. It should help the team gradually learn which categories fit which structures, which execution factors actually work, how each factor is achieved, which factors can be reused for new SKUs, and which factors only look reasonable but fail in real publishing results.

## Brand Personality

Professional, decisive, operationally sharp.

The interface should feel like a serious internal growth system rather than a generic admin template. The home page may carry a polished product-brand impression, while business pages should prioritize speed, clarity, evidence, and durable repeated use.

## Anti-references

Avoid low-fidelity wireframe-like pages, generic card-grid dashboards, decorative AI-themed dark interfaces, marketing landing-page composition, and pages that look disconnected from the real workflow.

Do not make every module visually identical. Each module should match its job: evidence review, factor library, SKU management, content production, image assets, variant generation, and result feedback need different information density and interaction patterns.

Avoid relying on real product or creator imagery in the home hero. The home page should use abstract system, data, and workflow visuals instead.

## Design Principles

1. Make the closed loop visible. Users should always understand where a task is in the path from viral video to reusable factor to SKU production to performance feedback.
2. Separate observation from judgement. Viral video analysis must first capture objective segment evidence, then make business judgements about structure and execution factors.
3. Treat SKU production as a connected chain. SKU files, matched factors, content generation, variant generation, publishing results, and factor updates must feel linked, not like unrelated pages.
4. Keep local data authoritative. The local database is the primary source of truth; Feishu is a synced collaboration layer with retryable sync states.
5. Use polish where it helps trust. The home page should feel like a real product; dense operational pages should be precise, readable, and efficient.

## Accessibility & Inclusion

Target WCAG AA contrast for text and controls. All important actions must be keyboard reachable, visible focus states must be preserved, and status should not rely on color alone. Motion should be restrained and respect reduced-motion preferences. Tables and long forms should favor readable density over tiny text.
