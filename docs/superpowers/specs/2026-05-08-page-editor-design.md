# DuoLe 页面编辑器第一版设计

日期：2026-05-08

## 背景

DuoLe TikTok Growth Studio 当前首页和业务页需要频繁调整视觉比例、模块排版、字段展示和按钮入口。如果每次都直接改代码，容易产生样式冲突、误删文件、海报比例反复调试、页面状态不可回滚等问题。

第一版页面编辑器的目标，是让使用者可以在本地系统里安全地调整首页和核心业务页，而不是直接编辑源码。

## 产品定位

编辑器采用混合模式：

1. 页面内快速编辑：在真实页面上打开编辑模式，直接调整常用排版和内容。
2. 独立三栏编辑器：进入专门编辑器处理复杂排版、字段显示、表格列、筛选项和按钮动作。

编辑器服务于公司内部运营人员，优先保证可控、可回滚、可预览，而不是一开始追求完全自由的低代码平台。

## 第一版页面范围

第一版支持 4 个页面：

- 首页
- AI 生图
- 爆款分析
- SKU 运营

其他侧边栏页面暂不开放编辑。后续可以在配置结构稳定后逐步加入。

## 第一版能力范围

### 支持

排版编辑：

- 调整模块顺序。
- 调整 hero 高度、模块宽度、模块间距。
- 修改模块标题、副标题、按钮文案。
- 替换图片资产。
- 调整模块显隐。
- 调整有限的颜色、圆角、阴影、背景样式。

字段显示：

- 控制业务页字段是否显示。
- 调整表格列顺序。
- 修改字段展示名称。
- 配置字段是否在筛选区出现。
- 配置字段在卡片、表格、详情区的展示位置。

按钮动作：

- 页面跳转。
- 打开弹窗或抽屉。
- 进入某个业务流程。
- 切换当前页面视图。
- 触发预定义动作，例如导入视频、进入分析、进入 SKU 管理。

保存与发布：

- 保存草稿。
- 预览草稿。
- 发布到真实页面。
- 回滚到历史版本。

### 暂不支持

- 自由编写 JavaScript 或脚本。
- 任意新增数据库表。
- 任意修改数据库字段类型。
- 自定义 AI 调用链。
- 自定义 Feishu 同步规则。
- 完全自由的数据绑定表达式。
- 多人协作和权限系统。

这些能力风险更高，应该等页面配置和版本机制稳定后再扩展。

## 用户入口

### 页面内快速编辑

顶部工具区增加“编辑页面”按钮。

进入编辑模式后：

- 页面模块显示选中边框。
- 模块出现拖拽手柄。
- 模块出现“编辑”和“高级编辑”入口。
- 可以快速调整文案、图片、高度、顺序、显隐。
- 点击“高级编辑”进入独立三栏编辑器，并定位到当前模块。

退出编辑模式后：

- 编辑控件隐藏。
- 页面回到正常使用状态。
- 未发布的草稿不会影响当前正式页面。

### 独立编辑器

路由建议：`/editor`

布局采用标准三栏：

- 左栏：页面列表、页面结构树、组件库。
- 中栏：实时画布，显示当前页面草稿。
- 右栏：属性面板，编辑选中页面、区块、字段或按钮动作。

顶部工具区：

- 页面选择。
- 设备预览。
- 保存草稿。
- 预览。
- 发布。
- 回滚。
- 返回真实页面。

## 保存方式

编辑器不直接改源码。第一版采用页面配置 JSON。

建议目录：

```text
src/config/pages/
  home.json
  ai-image.json
  viral-analysis.json
  sku.json
```

每个页面配置包含：

- 页面元信息。
- 布局区块。
- 模块内容。
- 字段显示规则。
- 按钮动作。
- 草稿和发布状态。

建议版本目录：

```text
src/config/page-versions/
  home/
  ai-image/
  viral-analysis/
  sku/
```

每次保存草稿生成一个版本文件。发布时记录当前发布版本。

## 配置结构草案

```json
{
  "pageId": "home",
  "title": "首页",
  "status": "draft",
  "publishedVersion": "2026-05-08-001",
  "layout": {
    "type": "app-shell",
    "sections": [
      {
        "id": "hero",
        "type": "hero",
        "visible": true,
        "order": 1,
        "style": {
          "height": 430,
          "backgroundImage": "/hero-new.webp"
        },
        "content": {
          "eyebrow": "TikTok Growth Studio",
          "headline": "把爆款流量变成销量资产",
          "body": "从内容灵感、购物信号到 SKU 任务，沉淀成下一批短视频的可复用打法。"
        },
        "actions": [
          {
            "id": "import-video",
            "label": "导入爆款视频",
            "actionType": "navigate",
            "target": "/viral-analysis/import"
          }
        ]
      }
    ]
  }
}
```

业务页配置在此基础上增加字段区：

```json
{
  "fields": [
    {
      "id": "skuName",
      "label": "SKU 名称",
      "visible": true,
      "tableColumn": true,
      "filterable": true,
      "required": true
    }
  ]
}
```

按钮动作只允许使用预定义动作类型：

- `navigate`
- `openModal`
- `openDrawer`
- `switchView`
- `runPresetAction`

## 发布流程

编辑流程：

1. 用户进入编辑模式。
2. 修改页面配置。
3. 点击保存草稿。
4. 系统生成草稿版本。
5. 用户预览草稿。
6. 用户确认后发布。
7. 发布版本成为真实页面配置。

回滚流程：

1. 用户打开版本记录。
2. 选择历史版本。
3. 预览历史版本。
4. 点击恢复为草稿或直接发布。

安全规则：

- 未保存修改离开页面时提示确认。
- 发布前必须预览或显示变更摘要。
- 发布失败时保留当前线上版本。
- 配置解析失败时页面回退到默认内置配置。

## 数据流

运行态页面读取已发布配置：

```text
published page config -> page renderer -> homepage / business page
```

编辑器读取和写入草稿配置：

```text
editor state -> draft config -> preview renderer -> publish -> published config
```

第一版可以先使用本地 JSON 文件模拟保存。后续如果引入本地数据库，可以把 JSON 配置迁移到数据库表，但外层配置结构保持一致。

## 组件边界

建议新增模块：

- `src/config/pages/`：页面配置。
- `src/editor/`：编辑器页面和编辑器状态。
- `src/page-renderer/`：根据配置渲染页面。
- `src/page-editor/`：页面内编辑模式控件。
- `src/config/page-actions.ts`：预定义按钮动作映射。

现有首页和核心业务页逐步改为由配置驱动。迁移时保留当前视觉作为默认配置，避免重新设计。

## 视觉要求

编辑器本身应该是安静、清晰、工作台式界面：

- 左栏深色或浅色都可以，但要和主产品侧栏区分。
- 中间画布优先展示真实页面比例。
- 右侧属性面板要分组清楚：内容、布局、字段、动作、版本。
- 编辑控件只在编辑模式出现。
- 不使用花哨装饰，不影响页面判断。

## 验收标准

第一版完成后应满足：

- 可以从首页顶部进入编辑模式。
- 可以进入 `/editor` 三栏编辑器。
- 可以编辑首页 hero 文案、图片、高度和模块顺序。
- 可以编辑 AI 生图、爆款分析、SKU 运营页面的字段显示、表格列、筛选项和按钮动作。
- 可以保存草稿。
- 可以预览草稿。
- 可以发布草稿。
- 可以回滚到历史版本。
- 配置损坏时不会导致页面白屏。

## 开放问题

- 第一版是否需要手机端画布预览。
- 第一版是否需要导入和导出配置包。
- 第一版是否需要把页面编辑器入口隐藏在开发模式里。

这些问题不阻塞第一版设计，可以在实现计划阶段决定优先级。
